01 / OVERVIEW

核心作用:它在解决什么问题

免费代理散落在各处:Telegram 频道里的一条条订阅链接、GitHub 代码仓库里的节点分享、机场网站的免费套餐。手动收集费时费力、质量参差、隔天就失效。Aggregator 把「找 → 验 → 洗 → 转 → 存」整条链路自动化,产出稳定更新、格式齐全、按质分组的订阅源。

🕷 多源爬取

Telegram 频道、GitHub 代码与 Issues、Google / Yandex 搜索、Twitter 时间线、任意网页、机场自动注册、自定义 Python 脚本插件,七类来源统一调度。

🔍 智能验证

用内置 Clash / mihomo 内核真实拨号测试每个节点:活性、延迟、倍率、落地位置,不合格的直接丢弃——「能连上」才叫代理。

🔄 格式转换

通过内置 subconverter 把同一份节点池转换为 Clash、V2Ray、SingBox 等格式,一次运行,多客户端通用。

💾 灵活存储

结果推送到 GitHub Gist、PasteGG 等云端剪贴板,得到稳定的订阅 URL;也可存本地文件,完全自主。

🔌 插件系统

爬不到的地方?在 crawl/scripts 下写一个实现 parse() / run() 的 Python 插件即可接入流水线。

🏷 分组管理

不同来源的节点可打上不同标签推送到不同分组(如 premium / free / backup),每组独立转换、独立存储。

举例 · 一句话理解 你在客户端里填一个 Gist 订阅 URL,每天早上自动多出几十个「昨天验证还活着」的免费节点——这背后就是 Aggregator 定时跑完一整趟流水线的结果。
02 / ARCHITECTURE

设计架构:五段流水线 + 两个入口

整个项目是一条单向数据流水线:爬取源产出原始订阅链接,逐级加工为可用节点,最终推送到存储。所有模块都在 subscribe/ 目录下,纯 Python 实现,Clash 与 subconverter 以预编译二进制形式内置,开箱即用。

数据来源加工环节
① 爬取 Crawl
TG / GitHub / Gist / Google / Yandex / 页面 / 脚本 → 提取订阅链接
→
② 注册 Airport
对机场站自动注册账号、领免费套餐、换取订阅(airport.py)
→
③ 聚合 + 验活 Clash
生成临时 Clash 配置,内核真实连通测试,按延迟 / 倍率过滤(clash.py)
→
④ 转换 Subconverter
按分组转换为 clash / v2ray / singbox 等格式(subconverter.py)
→
⑤ 推送 Push
上传到 Gist / PasteGG / 本地等后端,产出订阅 URL(push.py)

03 / PROTOCOLS

代理协议对比:怎么选、怎么取舍

README 声明支持的核心协议为:VMess、VLESS、Trojan、SS、SSR、Snell、Hysteria、Hysteria2、TUIC、AnyTLS、HTTP、SOCKS;subscribe/outbound/ 中还有 Mieru、SSH、WireGuard、OpenVPN 等扩展校验器。协议没有绝对优劣,差别在于「伪装能力、传输性能、客户端生态」三个维度的取舍。

协议传输基础伪装 / 抗封锁性能生态与客户端一句话定位
SS
Shadowsocks		TCP弱 — 加密流量特征明显,易被主动探测轻量、延迟低极广,几乎所有客户端老牌轻量之选,部署最简单
SSRTCP + 混淆中 — 在 SS 上加协议/混淆层,但项目已停更略高于 SS逐渐萎缩历史兼容用,新部署不推荐
VMessTCP(TLS 可选)中 — 自定义加密协议 + 时间戳校验加密层较多,开销偏大V2Ray 生态核心,支持广V2Ray 家族经典协议,成熟稳定
VLESSTCP(TLS/Reality)强 — 本体不加密,配合 XTLS / Reality 可伪装成正常 HTTPS 站点轻量,开销小于 VMessXray 系客户端当前主流新部署,抗封锁首选之一
TrojanTLS强 — 流量就是标准 HTTPS,直连访问一个真证书网站接近原生 HTTPS广泛「长得像正经网站」的老牌强伪装
HysteriaQUIC / UDP中 — 伪装为 HTTP/3 流量极高 — 拥塞控制激进,差线路也快官方客户端 + 主流内核高丢包 / 跨洋慢线路救星
Hysteria2QUIC / UDP中强 — 完整 TLS 1.3 握手,认证更简洁极高,配置比一代简单得多主流内核均已支持新一代 UDP 高速协议的事实标准
TUICQUIC / UDP中 — 基于 QUIC TLS低延迟,多路复用主流内核支持QUIC 阵营的低延迟选项
SnellTCP中 — 私有二进制协议高效轻量Surge 生态专属苹果系 Surge 用户的私有选择
AnyTLSTLS强 — 专为消除 TLS-in-TLS 指纹设计接近直连较新,mihomo 等已支持针对流量指纹检测的新方案
HTTP / SOCKS5明文 TCP无 — 无加密,内容可被直接审阅零开销通用标准只适合内网、本机中转等可信链路
举例 · 典型搭配 机场订阅大多是 SS / VMess / Trojan;自己搭新服务器优先 VLESS + Reality 或 Hysteria2;网络对 UDP 限速严重时退回 Trojan;只在本机 / 局域网转发用 SOCKS5 即可。
注意 · ENABLE_SPECIAL_PROTOCOLS VLESS、Hysteria2 等较新的协议默认可能不参与收集,官方工作流通过环境变量 ENABLE_SPECIAL_PROTOCOLS 控制是否纳入特殊协议。
04 / CONFIGURATION

配置详解:填什么、哪些必须填、结果长什么样

process.py 的一切都由一份 JSON 配置文件驱动,配合环境变量提供凭证。先理解一条「名字链条」,配置文件就读懂了一半:

sites[].push_to
每个订阅来源声明「我要去哪个分组」
→
groups.分组名.targets
分组声明「我要产出哪些格式,存到哪个存储项」
→
storage.items.存储项
存储项声明「最终写到哪个 Gist / 文件」
举例 · 名字链条串起来 站点 A 写 "push_to": ["premium"] → 分组 premium 写 "targets": {"clash": "premium-clash"} → 存储里要有 "premium-clash" 这个 item 指向你的 Gist 文件。三个名字(premium、premium-clash)必须对得上,缺一环节点就「流」不到终点。

4.1配置文件总骨架(process.py)

my-config.json —— 模板见 subscribe/examples/config.default.json{ "sites": [ ... ], // 已有订阅 / 机场站点(可自动注册) "crawl": { ... }, // 爬虫开关与各数据源配置 "groups": { ... }, // 输出分组、格式与归一化 "storage": { ... } // 存储引擎与存储项 }

4.2凭证与环境变量:哪些必须,哪些可选

变量必填?用于说明
PUSH_TOKENprocess.py 必需存储推送存储服务的访问令牌;engine 为 gist 时即 GitHub PAT(需 gist 权限)
SUBSCRIBE_CONF或用 -s 指定process.py配置文件路径或远程 URL;两者给其一即可
PUSH_TOKENprocess.py 必需两者存储服务访问令牌;也可读公开 gist(兼作 GH_TOKEN 兜底)
GH_TOKEN可选 · 强烈推荐GitHub/Gist 爬虫无 scope 即可读公开 gist 与搜索 API,防限流;也可写进 .env
LOCAL_BASEDIR可选本地存储本地存储引擎的输出根目录,不设则相对项目根
WORKFLOW_MODE可选process.py0 爬取+聚合(默认) / 1 仅爬取 / 2 仅聚合
SKIP_ALIVE_CHECK可选两者true 跳过验活,速度换质量
SKIP_REMARK / ENABLE_SPECIAL_PROTOCOLS可选两者跳过备注更新 / 启用 VLESS、Hysteria2 等特殊协议

4.3支持的平台与爬取源配置(crawl)

Telegram 频道

telegram.channels 里按频道名配置(支持任意公开频道,频道名即键),每个频道可配 include / exclude 关键词与 push_to 分组,靠公共频道网页版翻页爬取,无需 TG 账号。

GitHub

github.push_to 必填;内置 3 组搜索模式(v2board 精确 / 泛化 token / sspanel 短链),代码 + Issues 双通道;patterns 可自定义扩展。配合 GH_TOKEN 防限流。

Gist 公开时间线

GitHub 无 Gist 搜索 API,本源扫描 /gists/public 最近公开 Gist,从文件内容提取订阅;GH_TOKEN 或 PUSH_TOKEN 都能读,无需额外权限。

Google / Yandex 搜索

默认关闭,设 "enable": true 打开;适合补充冷门源,但验证码风险高,建议给 exclude_sites 拉黑名单。

本地代理 proxy

探活通过后置入 HTTP(S)_PROXY,所有爬取(GitHub/Gist/TG/页面)与订阅验证均优先走代理;订阅验证直连失败也会再走一次代理复验。

自定义页面 / 脚本插件

pages 支持 {page} 占位符批量翻页;scripts 指定 plugin 执行自写 Python 插件,任何「要登录 / 要签名」的站点都能接。

4.4sites 站点配置要点

字段必填?默认说明
name必需—唯一标识,用于日志与节点命名
push_to必需[]推送到哪些分组,不能为空
subscribe 或 domain二选一—已有订阅链接(填了就跳过注册);或机场域名,由注册器自动注册领套餐
include / exclude可选""正则过滤节点名,如 "香港|新加坡" / "过期|官网"
rename可选""重命名模板,"🇭🇰 {name}" 中 {name} 是原节点名
rate可选2.5最大流量倍率,超过即丢弃(机场「三倍流量」节点克星)
check_alive可选true是否参与 Clash 验活
count / coupon可选2 / ""自动注册的账号数与注册优惠码

4.6结果以什么形式存在

  • 每个「分组 × 格式」一个文件:如 premium-clash 产出 Clash YAML、free-v2ray 产出 Base64 订阅文本、singbox 产出 JSON。
  • 云端后端 → 订阅 URL:推送到 Gist 后,该文件的 raw URL 就是订阅地址,直接填进 Clash / V2RayN / Shadowrocket 等客户端。
  • 本地后端 → 文件树:<LOCAL_BASEDIR>/<folder_id>/<file_id>,如 output/premium/clash.yaml。
  • 附加持久化:crawl.persist 指定的存储项(默认 crawledsubs / crawledproxies)保存订阅池与节点快照 JSON,供下次增量复用;其中 订阅池只回写验活后确认产出过存活节点的订阅。
05 / HOW-TO

最佳实践:一步一步跑通

项目现在只有 process.py 一个入口。按下面 8 步操作,一次搭好可持续自动更新的代理池。每一步都标注了「为什么」。

5.1标准实践 · process.py 完整流水线(长期自动化)

1

复制默认配置作为起点

cp subscribe/examples/config.default.json my-config.json
为什么 默认模板包含全部字段及注释位,先跑通再裁剪,比从零写少踩 90% 的坑。
2

填 sites:喂给它已知的好源

有现成订阅就这样填(跳过注册,最省事){ "name": "my-airport", "subscribe": ["https://xxx.com/api/v1/client/subscribe?token=..."], "push_to": ["free"], "include": "香港|新加坡|日本", "exclude": "过期|官网|剩余", "rate": 2.0 }
为什么 include/exclude 在源头就过滤节点名,减少后续验活压力;rate 拦掉三倍率「刺客」节点。没有现成订阅就改填 domain,让注册器自动去注册领免费套餐。
3

配 crawl:打开你想要的爬取源

四路源:TG 频道 + GitHub 多模式 + Gist 扫描 + 本地代理"crawl": { "enable": true, "proxy": { "enable": true, "address": "http://127.0.0.1:7897" }, "telegram": { "enable": true, "pages": 5, "channels": { "oneclickvpnkeys": { "push_to": ["free"] }, "VmessProtocol": { "push_to": ["free"] } } }, "github": { "enable": true, "push_to": ["free"] }, // 内置3组搜索模式, patterns 可扩展 "gist": { "enable": true, "push_to": ["free"], "max_gists": 100 }, "google": { "enable": false } }
为什么 Google / Yandex 爬虫容易被验证码卡住,首跑就全开只会收获一屏报错;TG + GitHub + Gist 是产出最稳的三路,proxy 启用后它们全部优先走本地代理。记得导出 GH_TOKEN 防限流。
4

配 groups:决定产出哪些格式

groups 键名 = sites.push_to 里的分组名,要对应"groups": { "free": { "emoji": true, "targets": { "clash": "free-clash", "v2ray": "free-v2ray" } } }
为什么 targets 的键是 subconverter 的格式名,值是存储项键名——这就是 4.x 节说的「名字链条」中游,上下游必须同名。
5

配 storage:告诉它写到哪

engine 选 gist,items 里为链条终点准备同名存储项"storage": { "engine": "gist", "items": { "free-clash": { "username": "你", "gist_id": "...", "filename": "free.yaml" }, "free-v2ray": { "username": "你", "gist_id": "...", "filename": "free-v2ray.txt" } } }
为什么 一个 Gist 可容纳多个文件,按分组 × 格式各占一个文件即可;不想用云端就把 engine 换成 local,items 里填 folder_id/file_id。
6

设置凭证并小规模试跑

先小线程、长超时,验证链路通,再上强度# Windows PowerShell $env:PUSH_TOKEN="ghp_你的令牌" python subscribe/process.py -s my-config.json -n 16 -t 10000 # Linux / macOS export PUSH_TOKEN=ghp_你的令牌 python subscribe/process.py -s my-config.json -n 16 -t 10000
为什么 默认 64 线程对家宽与低配机器压力大,先 -n 16 -t 10000(10 秒超时)确认端到端能产出文件,再逐步加线程。常用参数:--check 只验活不推送、-c/--flexible 灵活邮箱注册、--invisible 隐藏进度条(适合日志环境)。
7

检查产出、客户端订阅

打开 Gist,确认 free.yaml 等文件已被更新且含有效节点;复制 raw URL 到客户端订阅。节点名带 emoji、地区、倍率,来自 rename 与 regularize 归一化配置。

为什么 验活只代表「运行那一刻能通」,免费节点衰减快,单次结果仅供验证链路,持续可用靠第 8 步的定时调度。
8

自动化:GitHub Actions 或本机定时

仓库自带 .github/workflows/process.yaml,fork 后只需填 Secrets# Settings → Secrets and variables → Actions: PUSH_TOKEN = ghp_xxx # secret SUBSCRIBE_CONF = https://.../my-config.json # secret,配置可托管在私有 Gist GH_TOKEN = ghp_xxx # 可选,提升爬虫额度 # 或者本机 crontab,每天 8:00 跑一次: 0 8 * * * cd /path/to/aggregator && PUSH_TOKEN=ghp_xxx python subscribe/process.py -s my-config.json
为什么 配置文件放私有 Gist 用 raw URL 引用,敏感信息不进仓库;官方 workflow 每天定时触发(cron 05 03/11 * * *),订阅内容随之每日刷新,这就是「代理池」的自我维持。

5.3常见故障速查

配置校验失败

python -m json.tool my-config.json 先验 JSON 语法;再检查「名字链条」:sites.push_to → groups 键 → storage.items 键是否全部对得上。

推送 401 / 无权限

PUSH_TOKEN 过期或权限不足,Gist 需要 classic PAT 且勾选 gist scope;PasteGG 等同理检查各自 API Key。

节点全军覆没

先确认本机网络能直连测试 URL(-u 可自定义);再放宽 -d 延迟阈值、增大 -t 超时;确认没把 SKIP_ALIVE_CHECK 与过滤条件同时调得极严。
